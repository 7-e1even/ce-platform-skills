# 审记事规则

CE 的「记事」每 5 分钟读一遍安静下来的对话,按一段抽事规则记下用户纠正、明说的规矩、返工后验证过的办法。
规则写得不对,每天都在漏记或记错,而且没人看得出来。你的事:每周看一遍它记得对不对,反复出现的问题改一处规则,
跑对比。**对比达标就自己换上**(用户授权过,不用等人);拿不准的存成提议,用户在 CE 后台「进化 · 记事规则」页点同意。
换过的用户在那一页一键就能撤回,所以达标时别犹豫,不达标时别硬换。

## 被定时任务叫起来时(每周)

1. `get_recorder_rule`:`enabled` 为 false 就报告「这个组织没开记事」后结束。记下 `text`(现在的规则)和 `read_until`。
2. `get_cursor(name="rule-review")` → `list_conversations(after=游标, quiet_minutes=60, limit=100, preview_chars=500)`,
   一页不够用 `next` 接着翻,**最多看 30 段**。跳过:
   - 更新时间晚于 `read_until` 的(记事还没读,不算漏记);
   - 评测、实验(批量出题、判分格式、只有一问一答没有真人);知识平台自己的对话(项目 `ce-platform`);
   - 应用或别的 agent 发起的自动任务(上下文压缩、只读审查、一次性调查这类,全程没有真人插话)。
3. 剩下的每段 `get_conversation`(长的用 `offset` 接着读,一段最多读 40000 字)。返回的 `evidence` 里 `actor` 是「记事」的,
   就是记事从这段记下的(`source` = 新记的,`corroborated` / `contradicted` = 印证 / 反驳已有记忆)。逐段对照原文判断:
   - **漏记**:用户纠正了智能体、明说了以后都要怎样、或返工后有确认地做成了,记事一条没记。
   - **记错**:记下的和原话意思不一样;把应用生成的任务指令当成用户的规矩;智能体自称修好了但没有任何确认。
   - **记了一次性的**:只对这一次成立的(临时文件名、某次的参数),或从一次经历推成了通则。
   - **该跳过没跳过**:评测、实验、自动任务里也记了东西。
   每个问题记下对话 id 和一句能说明问题的原话。
4. 看完存游标:`set_cursor(name="rule-review", value=<最后一页的 next>, actor="ce-rule-review")`。
5. **同一类问题至少出现在 2 段对话里**才改规则(一次的可能是模型偶然读错);没有就报告「这周不改」,工单设为完成,结束。
6. 改规则:在 `text` 上**只改一处**,针对最常见的那类问题,改动越小越好:加一句区分条件、一个反例、或把模糊的话说清楚。
   不改末尾要求的 JSON 输出格式。不要整段重写——重写会让对比里的差别分不清是哪句带来的。
7. 对比:`replay_recorder(conversation_ids=[...], rule=<改后的全文>, actor="ce-rule-review")`。对话挑:
   出问题的那几段(最多 6 段)+ 记事记得对的 3–6 段(看有没有改坏),一共不超过 12 段。
   过 2 分钟 `replay_result(replay_id)`;`running` 就再等 2 分钟,`lost` 就重跑一次。
8. 看报告:
   - 出问题的那几段,新版修好了几段(该记的记上了、不该记的没了)?
   - 正常的那几段,新版有没有多记、少记?两版用同一条规则时 20 段也会差 1–2 条(模型每次读得不一样),差别在这以内不算改坏。
   - 新版记下了但标着「哪组都不收,不记」的,是分组的事,不是规则的事,报告里提一句,别为它改规则。
   没修好或改坏了,换个改法再对比一次;**一次运行最多对比 2 次**。
9. 按对比结果三选一(报告模板见末尾,`report` 参数就填这份报告):
   - **达标 → 直接换上**:出问题的那几段至少一半修好、没有哪段变差;正常的那几段新版多记加少记合计不超过 2 条,
     而且少记的不是真人的纠正或规矩;两版都没有「没读出来」。
     `set_recorder_rule(rule=<对比时的全文>, reason="审记事规则:<改了什么,一句话>", report=<报告>, actor="ce-rule-review")`。
   - **有改进但拿不准**(修好了一些,但正常的差别略超噪声、或者有一段变差能说出原因):
     `propose_recorder_rule(rule=<对比时的全文>, report=<报告,写清为什么拿不准>, reason=..., actor="ce-rule-review")`,
     用户在 CE 后台批。新的提议会替掉没批的旧提议。
   - **没改进**:不换也不提议,报告「没找到好改法」和试过的改法。
   报告写进工单,工单设为完成,然后结束。不用等用户回复。

## 被评论叫起来时(用户在工单里回复了)

用户一般在 CE 后台批和撤回,不在工单里。真在工单里说了,就照做:

- **同意**(提议还在等批时):`get_recorder_rule` 看 `proposal_pending`;从工单里「提议的完整规则」那条评论取全文,
  `set_recorder_rule(rule=<一字不差>, reason=..., report=<原报告>, actor="ce-rule-review")`,回复「已换上」。
- **要改**:按用户的话改,重新对比(第 7、8 步),再按第 9 步处理。
- **撤回**:`get_recorder_rule`,把 `previous` 原样设回去(`previous_custom` 为 false 就传空字符串 = 内置规则),回复「已撤回」。

拿不准用户的意思就回复问一句,不要动规则。

## 不要做

- 对比没达标,不调 `set_recorder_rule`(拿不准就 `propose_recorder_rule`)。
- 不改、不删、不新建记忆(记错的那几条交给用户决定,报告里列出来就行)。
- 一次只改规则的一处;不删输出格式。
- 不把对话原文、密钥、令牌贴进工单;原话只摘一句,不超过 60 字。

## 报告模板

````
看了:对话 N 段(跳过 记事还没读 a、评测和实验 b、自动任务 c、平台自己的 d)
记事在这 N 段里:新记 x 条,印证 y 条,反驳 z 条
发现的问题:
- <漏记 | 记错 | 记了一次性的 | 该跳过没跳过>:<一句话>,<几段>(对话 id 前 8 位:…)
  例:「<原话一句>」
记错的记忆(要不要驳回由你定):<memory id 前 8 位>:<一句话>
提议:<改规则的哪一处,针对哪类问题,一句话>
  前:<原句>
  后:<新句>
对比(<replay_id>,共 M 段:出问题的 p 段 + 正常的 q 段):
- 出问题的:修好 i 段,没修好 j 段(<没修好的为什么,一句话>)
- 正常的:新版多记 k1 条、少记 k2 条(<是什么,一句话>)
- 合计:<replay_result 的 totals,旧 → 新>
结果:<已自动换上 | 已提议,等你在 CE 后台「进化 · 记事规则」批 | 没找到好改法,不换>
````

改过规则(换上或提议)时,完整规则另发一条评论,开头写「提议的完整规则(<replay_id>)」,全文放在 ```text 代码块里。
