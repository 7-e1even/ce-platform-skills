# 天才思维

两本书说的是同一件事:天才的思维是练得出来的习惯,而且**生成和检验分开做**——
生成时先求多、不给自己踩刹车;选择时严格,只留必要且充分的东西;最后的结论要能直接指导下一次行动。

下面五步可以连着用,也可以只用其中一步。每一步都写出来(列表或几行字),不要只在脑子里过。

## 1. 读懂:观察 + 换位

- **先写预期,再看材料。** 写下你以为发生了什么,再读原文,对照找出被预期过滤掉的东西。
- **换通道读。** 同一段对话分别看:用户原话、智能体的动作、工具返回和报错、先后顺序、语气变化。
- **单列「缺席」。** 该出现却没出现的:没跑的测试、没有的确认、用户没追问、没被用上的工具。
- **进入当事人。** 分别以当时的用户、当时的智能体的身份回答:「那一刻我知道什么、看到什么、为什么这样做?」
  这一步挡住事后诸葛亮——别把事后才知道的东西算成当时的失误。回答完要退出来,回到证据。
- **把「不对劲」先记下来。** 重试、回滚、用户改口、反复犹豫,都是「这里有问题」的信号;先标出来,不急着命名原因。

## 2. 抓本质:抽象

- **列多类特征**:功能、过程、因果、关系、组成,不只看表面现象。
- **删到不能再删。** 逐条问「去掉这一条,事情还会这样发生吗?」(删除法)。还会发生的就不是本质。
  但别删掉让经验**能被认出来、能被执行**的那个特征。
- **用「为了……」写出功能或因果**,压到一句话。
- **做两三个不同的抽象**,每个照亮一面;隔一会儿不看初稿重写一遍,两稿一致的部分才是稳定的内核。
- **手上有几件事时取不变量**:几件事里都在的才算模式;只有一件事,就只是一件事。

## 3. 发散:先多,再选

生成阶段不否决。冒出「不可能」「没人这么做」时,改问「为什么不?」(法律、伦理、安全约束除外)。

- **维度 × 取值。** 把事情拆成几个维度(谁的责任、哪一层、哪个时间点、缺了什么信息、用了什么工具……),
  每个维度写几个取值,**加一个「没有」**——「这一环根本不需要」常常是最好的框架;再交叉组合。
- **第一个想法先放着,沿同方向再推四步。** 每一步问「这太常见了吗?题目真的禁止这样吗?」
- **写出题面默认的那条规矩。** 看似无解时,先把默认的秩序说出来(「默认必须在这台机器上」「默认是代码问题」),
  再找包含它的更大秩序,在那里找解。只喊「跳出框框」不算数。
- **做变换**:反转因果、对调角色、推到极端、去掉一个约束、加一个荒唐的约束、假设「这次失败其实是对的」。
- **给候选标级**:同类里换一下(转移)、换到相邻领域(转接)、跨了好几类(跳跃)。全是转移就说明还没发散开,继续。
- **选。** 在文字里把每个候选「跑一遍」:如果它是真的,还应该看到什么?优先选能同时解释反常和缺席的那个;
  再问一遍「证据排除不了哪些候选?」排除不了的不要假装已经排除。

## 4. 举一反三:类比

- **比结构,不比外表。** 问「它在功能上、因果上像什么」,不是「看起来像什么」。
- **列对应表**:原情境的角色、步骤、因果,对应到新情境的哪个。对不上的单独列出来。
- **往前推一步出预测**:原情境里还有某个性质,新情境是不是也该有?这一步要能被检验。
- **在抽象阶梯上走**:先上一级到属类(这类事),再下到兄弟情境(同类的其他事)。上得太高就成了空话。
- **一次只改一个条件**:把经验里的一个参数逐步改大改小(规模、工具、环境、人),它失效的那一点就是适用边界,写进经验里。
- **换尺度**:一个回合 → 一整段对话 → 一类任务 → 所有用户,看它在哪一级还成立。

## 5. 检验

书里重生成、轻检验,所以这一步要自己做够:

- **删除法**:每个条件去掉后结论还成立吗?成立就删掉那个条件。
- **反例**:有没有符合这条经验、它却不成立的情况?有没有不符合、却也该这样做的情况?
- **造一个新例子**:构造一个满足前提的新情境,看经验是否还给出对的做法;给不出就说明写错了或写宽了。
- **多种写法一致**:把结论写成规则、正例、反例、触发条件、第一步动作,这几种说法要互相一致。
- **能不能行动**:以「将来读到这条经验的智能体」的身份读一遍——在它的上下文里会被想起来吗?读完知道第一步做什么吗?
- **新不等于真新**:先查库里、文档里有没有说过同样的事,自觉新颖不算数。

## 用在知识平台

| 角色 | 用哪几步 |
|---|---|
| 记录员(记事) | 1 全用;写候选的 then 时用 2 的「删到不能再删」。**不做 3、4**:记事只记发生过的事 |
| 写手(成规) | 2 → 3 → 4:同一件事写出「只适用这个项目 / 适用这类任务 / 通用」三层写法 |
| 验证员 | 5,外加 1 的「进入当事人」:在留出的对话里判断这条经验当时会不会帮上忙 |

## 常见失败

- 先入之见代替观察,只看到自己预设的那类原因。
- 换个说法当成新框架:形式变了,信息没变。
- 抽象成空话(「要更仔细」「注意沟通」),或删过头,丢了能执行的那一条。
- 用外表相似冒充结构对应,把原情境的细节硬搬过去。
- 一件事就宣称「看出了模式」。
- 只生成不检验;或者第一个框架就当终点。
