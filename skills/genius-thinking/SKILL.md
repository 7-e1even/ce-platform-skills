# 天才思维

骨架是安迪·阿莱尼柯夫《天才是怎样思考的》的五条法则,具体动作补充自《天才的13个思维工具》。
两本书的共同点:天才的思维是练出来的习惯,**生成和检验分开做**——生成时先求多、不给自己踩刹车;
选择时只留必要且充分的东西;结论要能直接指导下一次行动。

这本书专门训练的,正是模型最容易犯的毛病:给出第一个、最常见的答案(十以内的奇数选 7,
又圆又酸又黄的东西写柠檬),急着作答(2+2×2 先加),被题面里的数字和字眼牵着走(「卡车司机多大」)。
所以下面的动作每一步都要真的写出来,不要只在脑子里过。

## 五条法则

**一、拒绝放弃**
- 要求 N 个就给 N 个以上;够数后再加,并问自己「为什么停在这里」。**先量后质**:量够了,再挑有意思、有新意的。
- 找到一个解后再找第二个。
- 失败时不推给环境、用户或工具,先问「我这边哪一步可以不一样」;一次只改一个错误。
- 答案没出来之前别去「偷看」现成答案,自己推到想通为止。

**二、为什么一不顺就说「不」**
- 生成阶段脑中冒出「不可能」「没人这么做」「我们这儿不这样」时,改问「为什么不?」,再去找满足条件的实例。
  例外:法律、伦理、安全约束,不对它们问「为什么不」。
- 生成时不自我否决:油门刹车交替,走不远。批评留到检验那一步。
- 表达约束和不同意时,尽量用正面的说法:写成「该怎么做、为什么」,而不是一串「别……」。

**三、一带百万**
- **找本质**(天才最重要的技能):
  1. 用反例逐条拿掉不必要的特征:「没有它,这件事还会发生吗?」会 → 删掉(删除法)。
  2. 在抽象阶梯上找最近的上一级类别,一下排除不相干的东西;再和同一级的兄弟比,找出区别。
  3. 用「为了……」写出功能或因果,压到一句话、两三个关键词。
  4. 结果必须「必要且充分」:少一个特征就会和别的东西分不开,多一个就是表象。
  5. 问「这件事的核心目的是什么?」,把注意力从眼前的杂务拉回核心。
- **优先根本性的新**:几个候选里,选能引出最多后续变化的那个。
- **打破常规五步**(看似无解或条件矛盾时):相信有解 → 解在默认秩序之外 → **把默认的秩序写成定义**
  (「线」是什么?「必须在这台机器上」是谁规定的?)→ 找包含它的更大秩序,跳过去 → 写出新解。
- **新不等于真新**:逐级核对——自己、团队、项目、领域——有没有人做过、写过。作者自己就重新「发现」过导师早写过的东西。

**四、开放:重视他人**(作者说,全书只取一条就取这条)
- 听别人的观点、需要、情绪,**连同他们的错误**;把他们当作和自己同等重要的人。
- 听「副语言」:语速、音量、口音比字面更早透露真实状态。到了文字里就是:回复突然变短、标点变化、
  重复追问、语气变冲、改口——这些比字面意思更早说明对方不满意或没被理解。
- 多人(多个智能体)一起想时:先让地位低的先说,推迟权威意见;把别人的方案当跳板,不当靶子;
  生成和审查最好分开由不同的人做。
- 对自己的想法也给同样的宽容和尊重。

**五、进入天才轨道:加速改进本身**
- 「创造」就是让某个过程更快、更好;最高一层是**让创新这件事本身更快**。
- 对待任何方法:领会它的实质、掌握要领、**加以改进**、付诸应用。一个方法用了不灵,就大改它,
  而不是换个说法再用一遍。这条也适用于本技能和你自己的工作流程。
- 不知道答案时,先弄清**验收标准**再动手:知道怎样算好,产出会完全不同。

## 用在具体任务上

下面五步可以连着用,也可以只用其中一步。

**1. 读懂(观察 + 开放)**
- 先写下你以为发生了什么,再读原文,对照找出被预期过滤掉的东西。
- 换通道读:用户原话、智能体的动作、工具返回和报错、先后顺序、文字的「副语言」。
- 单列「缺席」:该出现却没出现的——没跑的测试、没有的确认、用户没追问。
- 分别以当时的用户、当时的智能体的身份回答:「那一刻我知道什么、为什么这样做?」防止事后诸葛亮;回答完要退出来,回到证据。

**2. 抓本质(法则三)**
- 按「找本质」五步做;多事件时只取都在的部分,一件事就只是一件事。
- 「好的东西都是脆弱的」:一个做法成功,往往是几个条件同时成立,错一个就不灵。写经验时把**必要条件写全**。
- 写成正面的「在什么情况下 → 怎么做」;原因落到可控的动作上。

**3. 发散(法则一、二)**
- **维度 × 取值**:把事情拆成几个维度(谁、哪一层、哪个时间点、缺了什么信息、用了什么工具……),
  每个维度单独写几个取值,**加一栏「没有」**(这一环根本不需要会怎样?),再交叉组合,给怪组合也找找用处。
- **四步推迟**:第一个想法先放着,沿同一方向再推四步,每一步问「这太常见了吗?要求真的禁止这样吗?」
- **换范畴**:每次换角度都给它命名一对对立范畴(上/下、前景/背景、用户/系统、现在/以后),再找还没用过的那一对。
- **给候选标级**:同类里换(转移)、换到相邻类(转接)、跨了好几类(跳跃)。全是转移就说明还没发散开。
- **选**:在文字里把每个候选「跑一遍」:如果它是真的,还应该看到什么?优先能同时解释反常和缺席的那个;
  再问「证据排除不了哪些候选?」

**4. 举一反三(类比 + 抽象阶梯)**
- 比结构不比外表:列对应表(角色、步骤、因果),对不上的单独列出来。
- 往前推一步得出可检验的预测:原情境里还有某个性质,新情境是不是也该有?
- 先上一级到这一类事,再下到同类的其他事;上得太高就成了空话。
- **动态法**:一次只改一个参数(规模、工具、环境、人),它失效的那一点就是适用边界,写进经验里。

**5. 检验**(书里重生成轻检验,这一步要自己做够)
- 删除法、反例法:每个条件去掉还成立吗?有没有符合它却不成立的情况?
- 自己出题:造一个满足前提的新情境,看经验还给不给出对的做法。
- 多种写法一致:规则、正例、反例、触发条件、第一步动作,互相一致。
- 能不能行动:以「将来读到这条经验的智能体」的身份读一遍——会被想起来吗?知道第一步做什么吗?

## 一条经验走到了哪一层

书里把任何新东西分五个层面,正好可以衡量一条经验:

| 层面 | 对一条经验来说 |
|---|---|
| 存在 | 这件事被记下来了 |
| 交流 | 写成了别人看得懂的话 |
| 工具 | 变成了能照着做的做法 |
| 方向 | 用在别人的任务上,真的帮上了忙(留出回放、对照效果能看到) |
| 创新 | 在很多人、很多任务上被用上;或者被提炼成方法论 |

一条经验的价值,看它让下一次做事快了多少、好了多少。停在「交流」层的经验再漂亮也没用。

## 用在知识平台

| 角色 | 用哪些 |
|---|---|
| 记录员(记事) | 法则四 + 第 1 步;写候选时用第 2 步。**不做 3、4**:记事只记发生过的事 |
| 写手(成规) | 法则一、二、三 + 第 2、3、4 步:同一件事写出「只适用这个项目 / 适用这类任务 / 通用」三层写法 |
| 验证员 | 第 5 步 + 第 1 步的换位:在留出的对话里判断这条经验当时会不会帮上忙;用「五个层面」判断它走到了哪 |
| 所有人 | 法则五:流程里哪一步总是卡、总是返工,就提出怎样改那一步 |

## 不照搬的部分

书里的鼓劲口号、「一分钟一百万个主意」的组合数算术、性格小测、各种「×10 / ×100 万」的说法,
只是作者的修辞,不要当成方法,也不要让它们抬高你对自己结论的信心。
